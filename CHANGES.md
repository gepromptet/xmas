# Changes in xmas, newest first

## Version 2

What a user of xmas can do now that they could not before:

- Give a system a budget: `MAS(..., budget=Budget(max_cost_usd=2.0, max_wall_s=600, max_calls=40))`. A call starts only while the run is below every limit, so a budget of 0 spends nothing. When a limit is reached the run ends with status `over_budget` instead of an exception, and the message names the limit, the amount and the call it refused. A module spends from the budget of the system around it.
- Read what every call cost: each record carries latency, cost in USD, the provider's token counts (cached and reasoning tokens included where the provider reports them), the finish reason, the error kind and the model that actually served the call, next to its binding name. Cost is never guessed as zero: it comes from the response when the gateway reports it, else from a price per model you pass to the client (`APILLM(price=TokenPrice(...))`), else it is unknown, and a sum with one unknown part is unknown. A cost budget refuses the next call while a cost is unknown and has no price.
- Keep the work of a failed run: the trace returns every record that finished before the failure, a run status (`ok`, `failed`, `over_budget`) and a typed error kind (money, rate limited, outage, timeout, length cut, bad format, refusal, budget, unknown). When one item of a batch fails, the other items keep their results and are not run again.
- Run plain code as a node: `MAS(..., code_nodes=[Code("count", uses="count_words")])` runs a function, or an MCP tool, between agents without a model call. The same function can also be a tool an agent calls.
- Pass structured data: every value is text or JSON, or a list of them at any depth (`list of text`, `list of list of json`). A JSON value or a list reaches a prompt as one line of JSON, a function gets the real object, not a string, and a list may be read where JSON is wanted. Every item of a list is checked, and an item may be `null`.
- Ask an agent for JSON with a fixed shape: `Agent(..., output_type="json", schema={"fits": {"type": "bool"}})`. The prompt ends with format lines no optimizer can drop; an answer that does not fit gets exactly one retry, then the run stops with a `bad_format` error.
- Let a node decide where the run goes: `when` (taken if a condition on its fresh answer holds), `else`, and `switch` (the edge whose case equals a field, for example `verdict.action`). Conditions are a small checked language, never code: fields, comparisons, `and`, `or`, `not`, `exists`, `len`, `visits`, `cost`, `elapsed`, and functions you register.
- Loop with a cap: a `while` edge goes back until its target ran `max_visits` times; then the record is marked capped and the `else` edge takes over.
- Route a failure by its kind: `on error: [timeout, outage]` (or `any`) sends the run to a fallback node and keeps the failed record, with the cost of every call the visit paid. A budget stop is never caught. A node whose only edges are `on error` edges ends the run when it succeeds.
- Fan in safely: a node fed by several edges is a merge, which runs on whichever edge arrives, or a join, which waits for one edge of each group and runs once per pass. The check refuses anything else and names the clashing edges. A value with several writers that are not alternatives needs `state: {value: {merge: last}}`, so the latest write wins.
- Put a whole system inside another as one node, a module, with `MASModule("shorten", inner, reads={...}, writes={...})`. The trace keeps the module's records nested, and `Trace.walk()` names the path to each one.
- Mark nodes `detached` (`Agent(..., detached=True)`, on any kind of node): no optimizer changes their prompt, model, wiring or edges. Topology search works on version 2 systems and keeps code nodes, modules, detached nodes, conditions and chains as they are.
- Read health signals on every trace: retried, bad format, routed errors, failed items, empty, stuck, unfilled placeholders, leaked markup, unusually long or short answers, items over their budget, how often each loop ran and whether it hit its cap, how much of each budget limit was used, and per chain how many items ran, failed and cost. They are for information only; a healthy run shows none.
- Find every wiring mistake when the system is built, listed together: a value read before anything writes it, two writers of one value, a placeholder the agent does not read, a JSON value sent where a function wants text, an unknown function, a condition on a field the answer form does not have.
- Run some nodes once per item of a list with a `for each` chain: `MAS(..., each={"writer": ForEach("page", "plan.slides", at_once=4, key="id"), "render": "page in plan.slides"})`, or `for each: page in plan.slides` in a spec. Items run in parallel, `at_once` caps how many at a time, and every record names its item and key. Outside the chain each value it writes is a list in item order. A failed item leaves `None` in those lists and the other items go on; a budget stop or an unrouted out-of-money error still ends the run. A `while` edge inside a chain repairs one item and caps per item.
- Start a run from several named values and read several outputs: `mas.run_state({"plan": ..., "house": ...})` checks every input before any call and lists every problem at once, and `MAS(..., outputs={"deck": "json", "notes": "text"})` puts each output's final value in `Trace.outputs`, with `Trace.output` the first. With declared outputs, several branches may end a run. The trace carries a `run_id` and the system's `graph_id`.
- Watch a run as it goes: `run_state(..., on_event=...)` hears each visit's and each item's start and end, with the node, the item and a status. A listener that raises is warned about once and gets no more events.
- Retry a node on a passing failure: `retry: {outage: 1}` runs an agent or code node again after an outage, a timeout or a rate limit. One record keeps the number of retries and the cost of every attempt.
- Read two values no node writes: `error`, the failure an `on error` edge routed to the node, and `run`, what the run has spent so far.
- Fill a placeholder from a value of another name with a read map, `Agent(..., inputs={"slide": "page"})` or `reads: {slide: page}`, and let agents share one prompt with `prompt: judge`; an optimizer changes a shared prompt for all of them.
- Cap the model calls in flight across a run with `Budget(max_parallel_calls=4)`, and flag an item that costs too much with `item_budget={"cost_usd": 0.05}`, which never stops it.
- Branches and `at once` items run together on any host: each graph run gets a pool of up to 64 threads (`xmas.runtime.BRANCH_THREADS`) instead of LangGraph's default of the host's cores plus four, which on a two-core machine left a side branch waiting behind the items. A batch (`run_many`) runs up to 16 queries at once (`xmas.runtime.BATCH_QUERIES`), each on its own pool.
- Pass pictures, sound, documents, tables and files as values: `image`, `audio`, `document`, `table`, `file` and lists of them. A value is a `Ref` (location, media type, size, checksum), never bytes, in state, records and traces, so `Trace.to_dict()` stays plain JSON. `run_state({"pages": [Path("slide-1.png")]})` refers to your files and checks each checksum on every read; a code node that returns a `Path` writes a copy into the store.
- Keep stored media in one folder, `XMAS_STORE` (default `~/.cache/xmas/store`), set in the environment and never in a spec. Each file is named by its checksum, so the same bytes are stored once and a rewrite is a new value.
- Say what each model accepts and produces: `APILLM(accepts=("text", "image"))`, `MAS(..., models={"vision-model": {"accepts": ["image"]}})`, or a `models:` section in a spec. When the system is built, the check refuses an agent that reads an image on a model that accepts only text, writes an image on a model that produces only text, or reads a document or a table directly, and says how to fix it.
- Show a model pictures and sound: an agent that reads an image or audio sends it as content parts, each item of a list labelled `[pages 0]`, `[pages 1]`, and its record shows a short marker such as `[image slide-1.png, image/png, 182 KB]` in place of the bytes. A tool agent sends the parts in its first message. A prompt with no picture keeps its exact request bytes.
- Turn a document into text and a table into rows with the two built-in conversion code nodes, `xmas.convert.document_text` (text, Markdown, HTML) and `table_rows` (CSV, TSV), so what a model was shown is a node in the graph.
- Get a picture as an answer: `Agent(..., output_type="image")` on a model that produces images stores the picture and writes its reference. Code nodes and MCP tools may write pictures too (`MCPTools(..., writes={"paint": {"png": "image"}})`).
- Put a person in the graph: `MAS(..., human_actions=[HumanAction("editor", "approve", reads=["draft"], writes="approval", question="Publish? {draft}")])`. A human action asks in one of four forms (`ask` with options, `judge` with a pair, `approve` with yes and no labels, `edit` of a value), with the question and the labels filled from the values it reads. Its answer is checked, written as JSON with who answered and when, and routed by the node's edges. The visit keeps a record of kind `human` with what was shown, the answer, a cost of 0 and how long it waited.
- Pause and resume a run: a question still open once every other branch has ended returns a `paused` trace, with the questions in `Trace.pause`. `mas.answer(run_id, answers)` keeps answers at any time, and `mas.resume(run_id, answers)` goes on, in the same process or, with a file store (`MAS(..., store="runs.db")` or `XMAS_RUNS`), after a restart. A paused chain item or module never holds its siblings. The budget counts on from the pause, and the wait is not wall time. A question with `timeout_s` takes its `default` once due. A host's `asker=` posts each question once and may withdraw it; `run`, `run_batch` and the optimizers never wait, and `ReplayAsker` answers from recorded runs.
- Every run is logged to one file by default, `${XDG_DATA_HOME:-~/.local/share}/xmas/runs.sqlite`; `XMAS_RUNS` or `[store] runs` move it, and `XMAS_RUNS=:memory:` or `MAS(..., store=":memory:")` turns it off. Every `run`, `run_batch`, `run_state`, `resume` and `predict`, version 1 included, writes as it goes: the run, each record the moment it is kept (inputs, outputs, raw answer, rendered prompt, cost, latency, model, item, visit, error), each event, each model call with its parameters (never a key), and each question and answer. Rows are only added, so a run whose process dies keeps what it finished. `RunStore.trace(run_id)` rebuilds a trace, `RunStore.runs(status=..., system_id=..., limit=...)` lists runs, and `xmas runs` and `xmas trace <run id>` show them from the shell.
- Stop a run: `mas.stop(run_id)` ends a running run within moments. No call, code node or item starts after it, waits end, and a model call in flight is cut. The trace has status `stopped` and keeps every record so far, a visit cut after a call included. A paused run is marked stopped and its questions withdrawn, and so are the open questions of a run stopped while it runs. `run_state(..., run_id=...)` lets the host name the run.
- Keep a cut answer: `APILLM(stream=True)` streams each answer, so a call cut by a stop keeps the text received so far. The default request is unchanged.
- Race branches: all `first of` edges of one node race their targets, and the first to finish writes. The other calls are cut, and each loser keeps a record with `lost` set and the cost it paid. A code node that races runs to its end and its writes are dropped. Inside a chain each item races on its own.
- Write all of this in a spec file of version 2 (`version: 2`), and draw or name a system from `MAS.describe()`, plain data with an `id` that does not change when only a prompt does.
- Save any system as a `.mas` bundle: `mas.save("team.mas")` writes a folder (or, with `zipped=True`, one zip file) with the wiring in `xmas.yaml`, where each function lives in `callables.yaml`, one plain-text file per prompt under `prompts/` (an optional header holds only the answer's schema), each module's system under `modules/`, and `xmas.lock` with the checksum of every file and of each function's source. Saving again rewrites only the files whose content changed, so comments in the other files stay. A bundle names its models and tool servers and never holds an endpoint, a key, a tool server's address, a budget or a run.
- Load a bundle with `MAS.load("team.mas")`: each function is found by its path and bound to its `params` (a bundle may name any code, so nothing is imported unless you pass `trust=True`; otherwise a function must be a `@tool` your program already imported, or be passed in `tools=`), a remote tool reaches the server its `server:` names in the configuration, and each model name gets a model on the configured endpoint. `llm=`, `llms=` and `tools=` supply your own instead, and `overlay={"agent": "model name"}` rebinds agents before anything is built.
- Give a model name parameters: a `models:` entry such as `editor: {model: llama-3.1-70b, max_tokens: 2000, timeout_s: 120, temperature: 0.2}` names the catalogue id the name stands for and sets `max_tokens`, `timeout_s`, `temperature`, `top_p`, `seed` or `reasoning_effort` for the models `MAS.load` builds.
- Configure where models and tools are served in one place: the environment (`XMAS_BASE_URL`, `XMAS_API_KEY`, `XMAS_MODELS`, `XMAS_CONFIG`, `XMAS_TOOLS_KEY`, `XMAS_STORE`, `XMAS_RUNS`), then `~/.config/xmas/config.toml` with an endpoint, prices and streaming per model id, tool servers under `[tools.<name>]`, and the stores. A file that holds a key and that others can read gives a warning, and no key appears in a bundle, a record, a `repr` or a message.
- Catch a mistyped model name before a run: each name is looked up in the endpoint's catalogue (its `GET /models`, kept for five minutes per endpoint and key, or the configured list). A miss gives a `ModelNameWarning` with the closest ids, never a substitute, and the system refuses to run until the name is fixed. Offline, names go unchecked and nothing is refused.
- Check a system with `mas.verify(level)`: level 0 compares the bundle with its lock and the system in memory with the files; level 1 checks the wiring, renders every prompt, reads every examples file and looks up every model name, with no model call; level 2 runs the warm-up examples under a small budget (0.05 USD in all and 0.02 USD per example unless you set one), a code node's writes compared exactly and an agent's answer against its checks. The report lists each example with its cost and time. A report that is not ok warns once; `strict=True` raises `VerifyFailed`, and `MAS.load(path, verify=1)` verifies on load.
- Keep warm-up examples in the bundle: `examples/*.yaml` holds node cases (the values a node reads, what it wrote, checks such as `form: valid`, `equals`, `contains`, `matches`, `len`, `exists`, `near`) and run cases (the system's inputs, checks per output or node). `mas.save_examples(trace, nodes=[...])` records them from a run.
- Use the `xmas` command: `xmas init`, `check`, `show`, `run`, `diff` and `verify` work on bundles from the shell, with `--json` for `show`, `diff` and `verify`, `--trust` to import a bundle's functions, and an exit status of 1 when something is wrong (for `verify`, with `--strict`).

Names settled before the first release: a node that runs a callable is a `Code` node (earlier `Step`), a person in the graph a `HumanAction` (earlier `Human`), and a whole system as one node a `MASModule` (earlier `Box`). They live in `MAS.code_nodes`, `MAS.human_actions` and `MAS.modules`, in the spec sections `code_nodes`, `human_actions` and `modules` and in a bundle's `modules/` folder, and a record's kind is `code`, `human_action` or `module`. `detached`, an attribute of every node (`Agent(..., detached=True)`, `detached: true` in a spec), replaces the system's `frozen` list. The value helpers for pictures and files are `REF_KINDS`, `REF_TYPES`, `ref_kind()` and `coerce_ref()`; `media_type` keeps meaning a MIME type.

What changed in the format: a version 2 spec has `inputs`, `outputs`, `agents`, `code_nodes` and `modules` with typed `reads` and `writes`, `for each` and `retry` on nodes, `schema` and a shared `prompt` on agents, reads as a list or a map, `edges` that may carry `{when: ...}`, `{when: ..., max_visits: n}`, `{switch: ..., case: ...}`, `else`, `{on error: [...]}` or `first of`, a `human_actions` section after `modules`, and `detached` on any node, the sections `state`, `health` (length factor, minimum samples, extra leak patterns), `models`, `callables` and `prompts`. Models appear by name only, a remote callable names its server, and keys and addresses never appear. Trace and record dictionaries keep their keys in their order and add a key only when it is set.

What stays the same: version 1 files load, run and save exactly as before, and so do their optimizers. The request a one-agent system sends is checked byte for byte, as is the bare-prompt encoding of a single agent. promptolution's optimizers run unmodified, and the public calls `run`, `run_batch`, `predict`, `copy`, `to_yaml` and `from_yaml` keep their behaviour. Every tool call runs, since a tool call need not be idempotent. A failed plain call's error reads `RuntimeError: LLM batch failed: ...` as before; a version 2 failure reads `Type: message`. A version 1 trace gains a `health` key only when a signal fires. Three differences on xmas's own model class and tool agents: a permanent provider error (bad request, key or money refused) is sent once instead of six times, and `APILLM(full_response=False)` keeps the earlier behaviour for plain agents; a tool turn sends a permanent error once either way; and a tool agent whose last turn is cut by `max_tokens` or refused before it wrote anything fails with `length_cut` or `refusal`, as a plain agent does, instead of answering `""`.
